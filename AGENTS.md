# Project instructions

For Jiangmen-localized article preparation or publishing, use the project skill at `.agents/skills/publish-jiangmen-articles/` and read its platform playbook before operating any publishing platform.

Keep manuscripts, images, publication trackers, browser exports, credentials, cookies, tokens, and verification data under ignored local-only paths. Never commit them to GitHub.

Before any public push, inspect both the staged files and repository history for local manuscripts, media, progress records, credentials, cookies, tokens, and verification data. Never use a force-add to bypass the ignore rules.

All future article covers must be visually text-free. If a candidate cover contains title text, labels, promotional copy, text watermarks, or any other visible words, replace it with another approved image before saving, scheduling, or publishing.

Use approved source images without local downscaling or recompression. For named developments, use verified images from that development, and consult the local usage ledger or hashes to avoid unintended reuse.

On a new computer, inspect the current platform management pages before resuming so that an interrupted run does not publish duplicates. Recreate local automations only after confirming the current date, article mapping, and platform status.

For logged-in publishing pages, prefer the dedicated Chrome browser controller. Keep one clean management tab and one current editor tab. Do not switch to Windows-level computer control merely because a long-form editor is slow.

A browser timeout is an unknown outcome. Before repeating paste, save, schedule, or publish, inspect a fresh platform management page and resume from the first missing checkpoint. Record visible platform content IDs in the ignored local tracker.

If browser access is rejected by a site-safety policy, mark that platform as requiring user handling and continue other platforms. Do not change browser surfaces or use indirect control to bypass the refusal.
