# 江门多平台文章发布技能

这是一个可直接交给 Codex 使用的项目技能，用于准备、配图、审阅并发布江门本地化中文文章，支持：

- 今日头条
- 微信公众号
- 百家号
- 知乎
- 搜狐号

仓库只保存可复用的技能、流程和校验脚本。文章原稿、图片、发布进度、账号凭据、Cookie、验证码和平台导出数据始终保留在每位使用者自己的电脑中。

## 下载与本地使用

任何人都可以从公开仓库下载使用：

1. 在 GitHub 仓库页面选择 **Code → Download ZIP**，解压到本地；或者运行：

   ```powershell
   git clone https://github.com/dadiaoliyaqiao-max/jiangmen-article-publisher.git
   cd jiangmen-article-publisher
   ```

2. 安装并登录 Codex，在 Codex 中打开仓库根目录。
3. 初始化不会上传到 GitHub 的本地工作区：

   ```powershell
   py -3 .agents/skills/publish-jiangmen-articles/scripts/init_local_workspace.py
   ```

   如果电脑没有 `py` 启动器，可改用 `python3`，或让 Codex 使用其内置 Python 运行该脚本。

4. 把审核稿放入 `local-data/manuscripts/`，把批准使用的原始图片放入 `local-data/images/`。
5. 按生成的 `local-data/publish-manifest.example.json` 建立本批 `publish-manifest.json`。
6. 在浏览器中登录需要使用的平台。
7. 对 Codex 说：`使用 $publish-jiangmen-articles，先核对清单和平台状态，再继续发布。`

下载者可以在自己的本地副本中自由修改。公开访客不能直接写入本仓库的 `main` 分支；只有仓库所有者明确授予写入权限的账号才能修改原仓库。

## 每批开始前必须汇报

真正操作平台前，先向用户报告：

- 文章顺序和准确标题；
- 每篇目标日期、正文图片数量和封面；
- 每个平台是保存草稿、立即发布还是定时发布；
- 管理页查重结果和仍需处理的项目。

未完成这一步，不进入平台编辑器。

## 固定内容规则

- 使用审核通过的 Word 或等价富文本稿作为唯一正文来源。
- 把写作注意事项、内部备注和配图要求与可发布正文分开，内部说明不得进入平台正文。
- 正文整篇复制一次；标题和封面图单独填写。
- 图片放在对应文字下方，并保留准确的 `▲ 图片说明`。
- 图片说明不得写“非某项目现场/实景”，不得出现具体房号。
- 有明确楼盘名称的文章，优先使用该楼盘经核实的设计图或实景图，不得冒充项目来源。
- 使用本地图片哈希或使用记录避免跨批次重复配图。
- 所有封面必须经过视觉核验，画面内不得出现标题、标签、促销文案、文字水印或其他可见文字。
- 不主动缩小、压缩或重新编码原始图片。上传后核对平台服务器图片尺寸；平台自行压缩时记录源图与平台结果，不把平台缩图覆盖成本地原图。
- 定位使用江门，且不得编造楼盘、门店、项目案例、资历、奖项或客户事实。

## 默认平台策略

| 平台 | 默认动作 | 最终核验 |
| --- | --- | --- |
| 今日头条 | 使用平台原生定时，通常为北京时间20:00 | 管理页显示准确时间、状态和江门定位 |
| 微信公众号 | 保存完整草稿，不公开发布 | 草稿卡片有封面且无“内容不完整” |
| 百家号 | 使用平台原生定时，通常为北京时间20:00 | 提交成功及待发布或审核状态 |
| 知乎 | 保存完整草稿；按用户指定日期由 Codex 续作发布 | 管理页公开状态、文章ID或URL及图片尺寸 |
| 搜狐号 | 使用平台原生定时，通常为北京时间20:00 | 管理页显示准确日期和时间 |

这些是默认值，实际动作以用户当批授权为准。若用户明确要求知乎长期每日发布，自动任务在没有合格草稿时保持启用并于次日继续；不得因此发布未登记的历史草稿、空稿或重复稿。

## 稳定执行流程

1. 扫描 `local-data`，生成或确认唯一的文章映射和发布矩阵。
2. 运行清单校验：

   ```powershell
   py -3 .agents/skills/publish-jiangmen-articles/scripts/validate_publish_batch.py --manifest local-data/publish-manifest.json
   ```

   没有 `py` 启动器时同样可改用 `python3` 或 Codex 内置 Python。

3. 在编辑前打开各平台管理页，按精确标题和内容ID查重。
4. 每个平台保留一个干净管理页和一个当前编辑页。
5. 标题单独填写，完整富文本正文只粘贴一次，封面单独设置。
6. 等待图片上传与自动保存，再核验标题、首尾、图数、说明、封面和图片像素。
7. 提交草稿或定时后回到管理页，以平台状态为准更新本地进度。
8. 平台日期范围不足时保留完整草稿，按准确日期创建 Codex 续作任务，绝不使用近似时间。

浏览器超时表示结果未知，不表示失败。超时后先从新的管理页查重和核验，不能直接重复粘贴、保存、定时或发布。

如果浏览器控制器明确返回站点安全策略拒绝，应停止该平台自动操作并记录为“需用户处理”，不得换浏览器、脚本或 Windows 控制绕过。

## 完成口径

- `制作完成`：文章、图片、说明、标题、封面及所需草稿或定时均已准备并核验。
- `实际发布完成`：目标日期已到，平台管理页确认文章已经公开发布。

未来日期仍需知乎发布或平台补定时时，不得对外报告“全部完成”。

## 隐私与仓库安全

`.gitignore` 已排除：

- `local-data/` 及其他本地制作目录；
- Word、PDF、正文HTML、图片和视频；
- 发布进度、浏览器导出、Cookie、令牌和凭据。

不要使用 `git add -f` 强制提交这些文件。公开前应同时检查当前工作树和完整 Git 历史；一旦凭据曾进入提交历史，仅从最新提交删除并不足够，还必须撤销该凭据并清理历史。
