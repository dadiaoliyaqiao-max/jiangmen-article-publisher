# 江门多平台文章发布技能

这是江门本地化文章的 Codex 项目技能，用于准备、配图、审阅并发布到：

- 今日头条
- 微信公众号
- 百家号
- 知乎
- 搜狐号

## 在另一台电脑使用

1. 安装并登录 Codex 与 GitHub Desktop。
2. 克隆本私有仓库，并在 Codex 中打开仓库根目录。
3. 将文章和图片线下复制到仓库中的 `local-data` 文件夹，建议结构：

   ```text
   local-data/
     manuscripts/
     images/
     progress/
   ```

4. 在新电脑的浏览器中分别登录今日头条、微信公众号、百家号、知乎和搜狐。
5. 对 Codex 说：`使用 $publish-jiangmen-articles 继续发布任务`。
6. 先检查平台内容管理页和本地进度表，确认没有重复发布，再重建需要的定时任务。

## 固定发布规则

- 使用审核通过的 Word 富文本稿作为唯一正文来源。
- 正文整篇复制一次；标题和封面图单独填写。
- 图片放在对应文字下方，并保留准确的图片说明。
- 微信公众号默认保存完整草稿，由用户自行发布。
- 知乎保存完整文章，并按当天要求发布。
- 今日头条、百家号和搜狐优先使用平台原生定时发布，默认北京时间 20:00。
- 定位使用江门，且不得编造楼盘、门店、项目案例、资历或奖项。
- 登录、Cookie、二维码和验证码不通过 GitHub 迁移；出现验证时停止并交由用户处理。

## 稳定快速执行流程

1. 扫描 `local-data`，生成或确认唯一的发布清单和进度表。
2. 若已有 `publish-manifest.json`，先运行：

   ```powershell
   py -3 .agents/skills/publish-jiangmen-articles/scripts/validate_publish_batch.py --manifest <清单路径>
   ```

3. 在任何编辑前先检查五个平台的内容管理页，按精确标题核对已有草稿、定时和发布状态。
4. 浏览器发布优先使用 Chrome 专用控制，只保留一个干净的管理页和一个当前编辑页。
5. 标题单独填写，完整富文本正文一次粘贴，封面单独选择；等待平台图片处理和自动保存。
6. 浏览器操作超时后不立即重试，先从新的管理页检查平台是否已经完成该动作。
7. 记录平台内容 ID、封面、图片数、最终状态和定时时间，再更新本地进度表。
8. 平台定时范围不足时保存完整草稿，创建按日期映射的 Codex 后续任务，绝不改成错误的近似时间。

详细恢复规则见技能中的 `references/recovery-runbook.md`。

## 完成口径

- `制作完成`：文章、图片、说明、标题、封面、草稿或原生定时均已准备并核验。
- `实际发布完成`：所有目标日期已到，且每个平台管理页均显示文章已经发布。

未来日期仍需知乎发布或平台补定时时，不得对外报告“全部完成”。

## 不会上传的内容

`.gitignore` 已排除 Word、PDF、图片、视频、正文 HTML、本地进度、Cookie、令牌和凭据文件。请不要强制添加这些文件。
